# `.nvmrc` — Node sürümü (tek kaynak)

> Faz 21.9 · `TST-05` · K272. İçerik: `24` (major).

## Neden?

CI `node-version: "22"` ile, yerel ortam Node 24.18 ile, sunucudaki derleme Node 24.22.1 ile koşuyordu (Y6.5c).
`verify:*` betikleri Node üzerinde çalıştığı için çalışma zamanı farkı kapı sonucunu değiştirebilirdi. Sürüm artık tek
yerde:

| Okuyan | Nasıl |
|---|---|
| Yerel | `nvm use` / `fnm use` (Windows'ta nvm-windows `.nvmrc` okumaz: `nvm use 24`) |
| CI (`ci.yml`, `e2e.yml`) | `actions/setup-node` → `node-version-file: .nvmrc` (e2e'de `davetkart-frontent/.nvmrc`); `24` → en güncel 24.x |
| `npm` | `package.json` `"engines": {"node": ">=24 <25"}`: farklı sürümde `npm ci` **uyarır** (`engine-strict` kapalı, durdurmaz) |
| Sunucu derlemesi | backend `deploy/deploy-frontend.sh`: `node --version` `.nvmrc` ile uyuşmazsa UYARI, durdurmaz |

## Neden yalnızca major (`24`), tam sürüm değil?

Tam sürüm (`24.22.1`) her yama sürümünde üç yeri (yerel, CI, sunucu) aynı anda güncellemeyi gerektirir; güncellenmeyen
yer uyarı üretir ve uyarılar kanıksanır. Major aynıysa `verify` betiklerinin dayandığı davranış (ESM, `fetch`,
`node:test` …) aynıdır; güvenlik yamalarını CI kendiliğinden alır.

## Sürüm yükseltme (25'e geçerken)

1. `.nvmrc` → `25`, `package.json` `engines` → `>=25 <26`, `npm install --package-lock-only` (kilit kökündeki `engines`).
2. Yerelde `npm ci && npm run check && npm run e2e`.
3. Sunucuda Node 25 kurulumu (deploy uyarısı bunu hatırlatır).
